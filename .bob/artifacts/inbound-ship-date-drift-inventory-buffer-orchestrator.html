The Problem

In manufacturing and distribution, a single supplier delay email triggers a multi-hour manual scramble across SAP, Excel, freight brokers, and warehouse teams — while revenue exposure grows silently with every minute of inaction. The workflow is deterministic enough to automate yet complex enough to demand intelligence: it spans vendor SLA law, inventory reorder math, logistics cost optimisation, and high-stakes human governance — the exact intersection where a multi-agent AI system delivers measurable impact.

What It Does

The orchestrator ingests a supplier delay notification and runs a complete 4-step remediation workflow in under 60 seconds — from security screening to a 1-click human approval card — without any manual intervention across ERP, WMS, or freight systems.

1
Security Screening GCP Model Armor (Regional Endpoint) scans every inbound supplier payload for prompt injection, PII, and tool-poisoning before any AI model sees it. Cloud DLP provides a mandatory second layer of enterprise PII redaction.
2
ERP Impact Analysis The Memory Bank agent retrieves the vendor's SLA penalty clause and delivery history from Firestore. The ERP agent walks the Bill of Materials to find every downstream Sales Order at risk and calculates total revenue exposure in real time.
3
Parallel Sub-Agent Dispatch A Warehouse sub-agent raises a Transfer Order to rebalance inventory buffers across distribution centres. A Freight sub-agent simultaneously books the optimal shipping mode — air, ocean, or ground — constrained by cost-policy guardrails enforced through the A2A Gateway.
4
Remediation & Human Sign-Off A complete remediation plan — vendor credit claim, revised Sales Order dates, freight booking, cost justification — is assembled and pushed to the operations team as a 1-click approval card over WebSocket. Cloud Tasks schedules a 1-hour escalation reminder if no response arrives.

Challenges

Model Armor REP Endpoint

The global endpoint returns HTTP 403 even after TOS acceptance; the regional endpoint (modelarmor.{location}.rep.googleapis.com) is the required path and is not prominently documented.

Memory Bank Bootstrap Order

VertexAiMemoryBankService requires the Agent Engine's numeric ID, which only exists after first deployment — resolved with a deliberate two-pass deploy pattern.

ADK Type Hint Enforcement

Missing type annotations on FunctionTool parameters fail silently at agent startup rather than call time, requiring systematic auditing of all 6 tool modules.

Cross-Language Tracing

Linking Node.js and Python ADK spans in one Cloud Trace waterfall required explicit W3C traceparent injection and extraction on every cross-process HTTP call.

Accomplishments

All 7 Agent Platform Pillars

Every Google Agent Platform capability is fully implemented and validated — none mocked or skipped in production.

3-Layer Security Pipeline

Model Armor → Cloud DLP → local regex, with both before_model and after_model callbacks enforced on every LlmAgent invocation.

True Parallel ADK Execution

SequentialAgent hosting a ParallelAgent dispatches Warehouse and Freight sub-agents simultaneously, cutting sub-agent wall-clock time in half.

Zero-Trust Identity

GCP OIDC, Secret Manager, and Cloud Audit Logs throughout — zero plain-text credentials anywhere in the codebase or CI/CD pipeline.

What We Learned

Topology beats model choice

SequentialAgent + ParallelAgent with explicit output_key state handoff made the workflow deterministic, auditable, and unit-testable end to end.

Tool server pattern scales

One Node.js backend as the sole tool server keeps the Python ADK layer thin, stateless, and independently deployable across environments.

Fail-open is architecture

Every GCP integration being fire-and-forget means the orchestration workflow degrades gracefully in dev without real cloud credentials.

Security must be inline

The before_model_callback is the correct place to enforce enterprise security policy — not post-hoc output filtering that lets threats reach the model first.
